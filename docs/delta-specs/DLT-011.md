# Delta Spec: DLT-011 - Clear notification badge on tab activation and session cleanup

## Story

As a user with multiple tabs, I want notification badges to always disappear when I switch to a tab — regardless of *how* I activated it — so that I never see stale badges on tabs I'm already looking at.

## What It Does

Centralizes notification badge clearing into the tab activation path (`switch_to`) so that every activation mechanism (keyboard shortcut, sidebar click, hook command, tab close → focus, session restoration, new tab creation) automatically dismisses the target tab's badge. Additionally ensures that destroying a session clears its notification state before removing its sidebar tab, so the badge cleanly transitions to zero before the row is removed. After centralizing, the scattered `mark_read` calls in keyboard handlers, sidebar click, and dot-bar click are removed as redundant.

## Requirements

| ID | Requirement | Status |
|----|-------------|--------|
| R0 | Any tab activation path clears the session's notification badge automatically | Core goal |
| R1 | When a session is destroyed, its notification state is cleared from the store before its sidebar tab is removed | Must-have |
| R2 | Remove scattered `mark_read` calls from main-window callers that become redundant after centralization | Must-have |

## Acceptance Criteria

### Badge clearing on activation (R0)

- [ ] Given a session has unread notifications, when the user clicks its sidebar tab row, then the badge is cleared
- [ ] Given a session has unread notifications, when the user activates it via keyboard shortcut (Ctrl+Tab, Alt+PageUp/Down, Ctrl+1-9, Alt+Shift+PageUp/Down, Ctrl+Alt+PageUp/Down, Ctrl+Shift+PageUp/Down), then the badge is cleared
- [ ] Given a session has unread notifications, when a `focus-session` socket command targets it, then the badge is cleared
- [ ] Given a session with notifications is closed, when focus moves to the adjacent tab, then the adjacent tab's badge is cleared
- [ ] Given saved sessions are restored, when the active session index is restored, then that session's badge is cleared
- [ ] Given a new tab is created, when it becomes active, then any badge (if present) is cleared

### Session cleanup ordering (R1)

- [ ] Given a session with unread notifications, when it is destroyed, then `clear_session` runs before `sidebar.remove_tab`, so the badge transitions to zero before the row is removed
- [ ] Given a session with unread notifications, when it is destroyed, then the system tray count decrements correctly

### Scattered call cleanup (R2)

- [ ] Given the centralization is complete, then no `mark_read` calls remain in `keyboard.rs` (the 6 call sites)
- [ ] Given the centralization is complete, then the `mark_read` call in `wire_tab_lifecycle`'s click handler is removed
- [ ] Given the centralization is complete, then the `mark_read` call in the collapsed-bar dot click handler is removed
- [ ] Given the centralization is complete, then the dropdown's direct `mark_read` call in `show()` remains unchanged (it handles window visibility, not tab activation)

### No regressions

- [ ] Given all changes are applied, then all existing notification-related tests continue to pass
- [ ] Given a session receives a notification while active, then the notification is still suppressed (not added to the store)
- [ ] Given the dropdown window is shown via toggle, then its active session's badge is still cleared

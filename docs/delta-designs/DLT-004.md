# Design: DLT-004 - Open web pages in browser tabs

**Delta Spec**: [../delta-specs/DLT-004.md](../delta-specs/DLT-004.md)
**Status**: Draft

## Purpose

This document explains the design rationale for this delta: the modeling choices, data flow, system behavior, and architectural approach.

After implementation, the "Detected Impacts" section will guide reconciliation into feature design docs.

## Problem Context

Users working in seemux need to view web content (documentation, dashboards, search results) alongside terminal sessions without leaving the application. Currently, opening a URL means switching to an external browser, breaking the terminal-focused workflow.

The key constraints are:
- The browser must render inside a VTE terminal widget (the only embeddable terminal widget available in GTK4)
- seemux runs a single-threaded GTK event loop with `Rc<RefCell<T>>` state — no async runtimes
- Browser sessions must participate fully in the existing session system (sidebar, groups, persistence, notifications)
- The browser binary is fixed (not user-configurable), so availability varies by system

## Design Overview

Add a new session type — **Browser** — that spawns [Carbonyl](https://github.com/fathyb/carbonyl) (a Chromium-based terminal browser) inside a VTE terminal widget. Browser sessions are first-class sessions with distinct sidebar display (globe icon, page title, URL), URL tracking via Chromium DevTools Protocol HTTP polling, and a close-on-exit lifecycle.

The design introduces:
1. **SessionType enum** on the Session struct to distinguish Shell vs Browser sessions
2. **Browser session factory** in SessionManager that spawns Carbonyl with `--remote-debugging-port` for URL tracking
3. **URL polling** via HTTP GET to Chromium's `/json/list` endpoint, updating sidebar and persistence
4. **Adapted TabRow** display logic that switches icon, title, and subtitle based on session type
5. **URL input modal** (overlay dialog) and **context menu entry** for creating browser sessions

## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Add `SessionType` enum (`Shell`, `Browser`) to Session struct; store `url` and `page_title` fields on Session for browser sessions; include in `Session::new` and all session creation paths | |
| **S2** | Spawn Carbonyl via VTE `spawn_command` with `["carbonyl", "--remote-debugging-port=PORT", "URL"]`; detect missing binary (`which carbonyl`) before spawn and show error overlay | |
| **S3** | Close session on browser process exit — wire VTE `child-exited` signal to `destroy_session` for browser-typed sessions (no fallback to shell) | |
| **S4** | Extend TabRow display to adapt by session type: globe icon (`emblem-web` or `applications-internet`) for browser sessions, page title as title, URL as subtitle, skip git branch/PR detection | |
| **S5** | Track URL + title changes via HTTP polling of Chromium DevTools `/json/list` endpoint on an allocated port; GLib timeout polls every 500ms; updates sidebar title/subtitle and persists current URL | |
| **S6** | Add "Open in browser tab" GIO action (`open-in-browser`) with string URL parameter; add menu item to terminal context menu when a non-file URL is detected under cursor | |
| **S7** | Add URL input modal using existing overlay dialog pattern (DES-007): blank URL entry field, "Open"/"Cancel" buttons, auto-prepend `https://` on submit | |
| **S8** | Extend `SavedSession` with `session_type` (defaulting to Shell for backward compat), `url`, and `page_title` fields; serialize/deserialize browser sessions; skip restoration if Carbonyl not found | |
| **S9** | Register `Ctrl+Shift+O` keybinding for opening browser tabs (triggers URL input modal) | |
| **S10** | Browser sessions are always single-pane; split actions (Ctrl+Shift+H/E) are disabled for browser sessions — the session's SplitTree is always a single Leaf containing the Carbonyl VTE | |

## Components

### Implementation Structure

| Layer/Component | Responsibility | Key Decisions |
|-----------------|----------------|---------------|
| **Session model** (`session/mod.rs`) | `SessionType` enum, browser fields on Session | Enum-based type discrimination; url/page_title stored directly on Session (only populated for Browser type) |
| **Session manager** (`session/manager.rs`) | `create_browser_session(url)` factory, port allocation, URL poll timer | Allocates from a port range (19300+); uses `spawn_command` with Carbonyl args; starts GLib poll timer |
| **VTE terminal** (`terminal/vte_terminal.rs`) | No changes to VteTerminal itself — Carbonyl runs inside it like any command | Reuses existing `spawn_command` and signal infrastructure |
| **Sidebar TabRow** (`sidebar/tab_row.rs`) | Conditional display by session type | `set_session_type(SessionType)` method switches icon/metadata — for Browser type: sets globe icon, hides git branch/PR widgets, reuses `set_title()` for page title, reuses `set_subtitle()` for URL |
| **Actions** (`app/actions.rs`) | `open-in-browser` GIO action; context menu addition | Follows DES-004 (GIO Action Dispatch); "Open in browser tab" shown only for non-file URLs (same filter as existing "Open URL" item — `!url.starts_with("file://")`) |
| **Dialogs** (`app/dialogs.rs`) | `show_url_input_overlay` for browser tab creation | Follows DES-007 (Overlay Dialog Pattern); reuses `show_entry_overlay` pattern |
| **Keyboard** (`app/keyboard.rs`) | `Ctrl+Shift+O` keybinding | Added to `is_our_shortcut` match and handler chain |
| **Persistence** (`config.rs`) | `SavedSession` extended with browser fields | `session_type` defaults to Shell for backward compat (serde default) |
| **URL Polling** (new module or in `session/manager.rs`) | HTTP GET to Chromium's `/json/list` every 500ms | Uses `minreq` (synchronous, no async runtime); parses JSON response for url + title. 500ms chosen as balance between responsiveness and overhead — sidebar updates don't need sub-second precision |

### Cross-Layer Contracts

**Integration Points**:
- **SessionManager ↔ Sidebar**: Browser sessions call `sidebar.update_title()` for page title and `sidebar.update_cwd()` analog for URL display (or a new `sidebar.update_url()` method)
- **SessionManager ↔ URL Poll**: Poll timer closure captures session ID and sidebar reference; on URL/title change, updates Session fields and sidebar, marks persistence dirty
- **Actions ↔ SessionManager**: `open-in-browser` action calls `manager.create_browser_session(url)`
- **Keyboard ↔ Dialogs**: `Ctrl+Shift+O` calls `show_url_input_overlay()` which on submit calls `manager.create_browser_session(url)`
- **Context Menu ↔ Actions**: "Open in browser tab" menu item activates `win.open-in-browser` action with URL parameter

**Error handling**:
- Carbonyl not found: show error overlay dialog with installation instructions ("Install Carbonyl: npm install -g carbonyl"), no session created
- Carbonyl fails to start: VTE `child-exited` fires immediately → session destroyed (same as normal exit)
- CDP port unreachable: URL polling silently fails (up to 10 consecutive failures, then stops); sidebar shows initial URL only; title may still update via VTE's `window_title_changed` signal (OSC 2)
- Port collision: Carbonyl fails to bind port → child-exited with error → session destroyed, error logged with port number

### Shared Logic

- **URL normalization**: Auto-prepend `https://` if input lacks a protocol — shared between modal submit and context menu action
- **Port allocation**: Counter-based port assignment starting at 19300, stored in SessionManager — avoids conflicts between multiple browser sessions

## UI Layout

### URL Input Modal

```
╭────────────────────────────────╮
│ Open browser tab           [×] │
├────────────────────────────────┤
│                                │
│  URL                           │
│  [_______________________]     │
│  (placeholder: Enter URL...)   │
│                                │
│        [ Cancel ] [[ Open ]]   │
│                                │
╰────────────────────────────────╯
```

### Layout Explanation

**Purpose**: This is the URL Input Modal from the "Open Browser Tab via Keybinding" breadboard. It's the entry point for creating browser sessions via keyboard shortcut.

**Key elements**: URL text entry field with placeholder text, Cancel button (dismisses overlay), Open button (creates browser session with entered URL).

**Layout rationale**: Follows the existing `show_entry_overlay` pattern (DES-007) — centered card, label + entry + button row. Open button styled as `suggested-action` (primary). Matches the established overlay dialog conventions.

**Interactions**: Enter key submits (same as Open button). Escape key dismisses (same as Cancel). Empty input dismisses without creating a session. Input without protocol gets `https://` prepended automatically.

### Browser Tab Row in Sidebar

```
┌──────────────────────────┐
│ 🌐 Example Page Title    │  ← globe icon + page title
│ example.com/page         │  ← URL (display path)
│                     ●    │  ← status pill (same as shell)
│                       ×  │  ← close button
└──────────────────────────┘
```

Compared to shell tab row:
```
┌──────────────────────────┐
│ 📁 my-project            │  ← folder icon + folder name
│ ~/projects/my-project    │  ← display path
│ main   ●                 │  ← git branch + status pill
│                       ×  │  ← close button
└──────────────────────────┘
```

### Layout Explanation (Browser Tab Row)

**Purpose**: Shows browser session metadata in the sidebar, distinct from shell sessions at a glance.

**Key elements**: Globe icon replaces folder icon. Page title replaces folder name as the primary title. URL replaces display path as the subtitle. No git branch or PR badge (skipped for browser sessions). Status pill and close button unchanged.

**Layout rationale**: Visual distinction (icon + metadata swap) makes browser tabs immediately identifiable without breaking the tab row layout. Skipping git metadata avoids irrelevant noise.

**Interactions**: Same as shell tab rows — click to activate, drag to reorder, close button to destroy. Middle-click/peek behavior unchanged.

## Modeling

### Session Type Extension

```
Session
├── id: String (existing)
├── title: String (existing — shows folder name for Shell, page title for Browser)
├── status: SessionStatus (existing)
├── session_type: SessionType (NEW)
│   ├── Shell (default)
│   └── Browser
├── url: Option<String> (NEW — current URL for browser sessions)
├── page_title: Option<String> (NEW — current page title for browser sessions)
├── debug_port: Option<u16> (NEW — CDP port for browser sessions, not serialized)
├── cwd: Option<String> (existing — null for browser sessions)
├── ... (remaining existing fields)
```

`SessionType` is a simple enum without data — the URL and page title live as optional fields on Session, only populated for Browser type. This keeps serialization simple and avoids nested pattern matching.

`debug_port` is marked `#[serde(skip)]` — it's runtime-only, used by the URL poll timer.

### SavedSession Extension

```
SavedSession (JSON)
├── title: String (existing)
├── split_tree: SavedSplitNode (existing)
├── group_id: String (existing)
├── session_type: Option<SessionType> (NEW — defaults to Shell)
├── url: Option<String> (NEW — for browser session restoration)
├── page_title: Option<String> (NEW — for sidebar display on restore)
```

Backward compatibility: `session_type` uses `#[serde(default)]`, so old state files without this field deserialize as Shell sessions.

## Data Flow

### Browser Session Creation (via modal)

```
User presses Ctrl+Shift+O
    → keyboard handler calls show_url_input_overlay()
    → User types URL, presses Enter
    → normalize_url() prepends https:// if needed
    → manager.create_browser_session(url)
        → Session::new() with SessionType::Browser
        → allocate debug port (19300 + counter)
        → VTE spawn_command(["carbonyl", "--remote-debugging-port=PORT", url])
        → wire child-exited → destroy_session (browser lifecycle)
        → wire title_changed → update page title in sidebar
        → start URL poll timer (500ms GLib timeout)
        → register session in sidebar with browser icon
```

### Browser Session Creation (via context menu)

```
User right-clicks on URL in terminal
    → context menu shows "Open in browser tab" (for non-file URLs)
    → activates "win.open-in-browser" action with URL
    → manager.create_browser_session(url)
    → (same flow as above)
```

### URL + Title Tracking

```
Every 500ms (GLib timeout):
    → GET http://127.0.0.1:{debug_port}/json/list
    → Parse JSON array, find target where type == "page"
    → Extract url and title fields
    → If URL changed from last poll:
        → Update session.url
        → Update sidebar subtitle (URL display)
        → Mark persistence dirty (DES-003)
    → If title changed from last poll:
        → Update session.page_title
        → Update sidebar title
```

**CDP `/json/list` response format** (single page target):
```json
[
  {
    "id": "ABCDEF123",
    "type": "page",
    "title": "Example Page Title",
    "url": "https://example.com/page",
    "webSocketDebuggerUrl": "ws://127.0.0.1:19300/devtools/page/ABCDEF123"
  }
]
```

Target selection: find first entry where `"type" == "page"`. Ignore `browser` and `service_worker` entries.

**Error handling**:
- HTTP connection refused / timeout: silent failure, retain last known values. The poll runs on the next 500ms tick.
- JSON parse error: silent failure. Malformed response shouldn't crash the poll loop.
- Empty target array: treat as "no page loaded yet" — retain initial URL.
- Consecutive failures (10+): stop polling (Carbonyl likely dead). The `child-exited` signal handles cleanup.

### Session Persistence

```
On save (debounced):
    → For each session, map to SavedSession
    → Browser sessions: include session_type, url, page_title
    → Shell sessions: session_type defaults to Shell on load

On restore:
    → Load SavedSession array from JSON
    → Browser sessions: spawn Carbonyl with saved URL
    → If Carbonyl not found: skip session, log warning
    → Shell sessions: normal restore flow
```

### Session Destruction

```
Carbonyl process exits (user quit, crash, kill)
    → VTE child-exited signal fires
    → Session type is Browser → destroy_session(id)
        → Remove URL poll timer (cancel GLib SourceId)
        → Remove from sidebar
        → Remove from stack
        → Focus next appropriate session
    → (No "convert to shell" fallback)
```

### Split Pane Restriction

Browser sessions are always single-pane. The `create_browser_session` factory creates a `SplitTree::Leaf` with no split capability. When split actions (Ctrl+Shift+H/E) fire with an active browser session, the action is skipped — the shortcut event proceeds normally so it can reach other handlers. This constraint exists because Carbonyl renders to a single terminal widget and the "one URL per session" model doesn't map to multi-pane layouts. Future layout support (DLT-002) will enable side-by-side arrangement of separate sessions.

## Key Decisions

### Browser Binary: Carbonyl

**Choice**: Carbonyl (Chromium-based terminal browser)
**Why**: Only terminal browser that renders full modern web pages inside a VTE widget. Starts in <1s, runs at 60 FPS, idles at 0% CPU. Actively maintained (19k GitHub stars). Accepts URLs as CLI arguments.
**Sources**: [Carbonyl GitHub](https://github.com/fathyb/carbonyl), researched May 2026
**Options Researched**:
- **Lynx**: Text-only, no JavaScript/CSS, oldest terminal browser. `UPDATE_TERM_TITLE` option for title tracking but no modern web rendering.
- **w3m**: Lightweight, some table/frame support, no JavaScript. No documented OSC sequence emission.
- **Browsh**: Firefox headless + automation protocol. 50x more CPU than Carbonyl for same content. More complex dependencies (requires Firefox).
**Why This Over Alternatives**: Carbonyl is the only option that renders modern web pages (CSS, JavaScript, WebGL, video) inside a terminal at native performance. The alternatives either lack modern web support (Lynx, w3m) or have prohibitive resource costs (Browsh).
**Consequences**:
- Pro: Full web rendering in terminal, excellent performance, active development
- Con: Requires Chromium dependencies on Linux; npm or binary installation; no fullscreen mode yet

### URL Tracking: CDP HTTP Polling

**Choice**: HTTP polling of Chromium DevTools `/json/list` endpoint every 500ms
**Why**: Carbonyl passes unknown CLI args through to Chromium, so `--remote-debugging-port` works out of the box. The `/json/list` endpoint returns both `url` and `title` fields in a simple JSON array. No WebSocket, no async runtime, no Carbonyl modification needed.
**Sources**: Chromium DevTools Protocol documentation, Carbonyl source code analysis (`bridge.rs` line 126: `.args(cmd.args)`)
**Options Researched**:
- **Fork Carbonyl + add OSC 7 emission**: Clean but requires maintaining a fork. The `push_nav()` method in Carbonyl's `Navigation` struct already has the URL — adding `\x1b]7;{url}\x07` would be ~3 lines. VTE handles OSC 7 via `current_directory_uri_changed`. Rejected because it adds a fork maintenance burden.
- **WebSocket CDP events (Page.frameNavigated)**: Near-instant updates, well-documented. Rejected because it requires a WebSocket client library, async handling, and more complex message parsing — overkill for sidebar URL display.
- **Terminal output parsing**: Fragile, depends on Carbonyl's internal UI layout. Rejected.
- **Initial URL only (no navigation tracking)**: Violates R9 (must-have requirement). Rejected.
**Why This Over Alternatives**: Simplest approach that works without modifying Carbonyl. Uses Chromium's built-in CDP endpoint. `minreq` (synchronous HTTP client) fits GTK's single-threaded model perfectly — no tokio needed.
**Consequences**:
- Pro: Zero modification to Carbonyl, simple implementation, synchronous fits GTK model
- Pro: Gets both URL and title from single endpoint
- Con: 500ms latency on URL updates (acceptable for sidebar display)
- Con: No same-document navigation tracking (hash changes, pushState) — `/json/list` may not reflect these
- Con: Requires `minreq` dependency (~50KB)
- Con: Debug port open on localhost while session is active (127.0.0.1 only, acceptable risk)

**HTTP client choice**: `minreq` chosen over `ureq` (larger, more features than needed), `reqwest` (requires tokio runtime), and `attohttpc` (similar scope but less widely adopted). `minreq` provides exactly what's needed — synchronous GET with JSON response body — in ~50KB, with no dependency on an async runtime.

### Keybinding: Ctrl+Shift+O

**Choice**: `Ctrl+Shift+O` (O for "Open in browser")
**Why**: `Ctrl+Shift+B` was the original candidate but is already used for sidebar collapse toggle. `O` is a natural mnemonic ("Open browser") and fits the existing `Ctrl+Shift+` modifier pattern.
**Alternatives Considered**:
- `Ctrl+Shift+B`: Already used for sidebar collapse (line 89 of `keyboard.rs`)
- `Ctrl+Shift+N`: Claimed in `is_our_shortcut` list but not explicitly handled — confusing
- `Ctrl+Shift+G`: Same situation as N
**Consequences**:
- Pro: Memorable mnemonic, consistent with existing shortcuts
- Con: None significant

### Session Type Modeling: Fields on Session (not enum variants)

**Choice**: `SessionType` enum as a field, with `url` and `page_title` as separate `Option<String>` fields
**Why**: Keeping the enum simple (no associated data) and putting browser-specific data in optional fields makes serialization straightforward and avoids nested pattern matching throughout the codebase. The `debug_port` is `#[serde(skip)]` since it's runtime-only.
**Alternatives Considered**:
- **Enum with associated data**: `SessionType::Browser { url: String, debug_port: u16 }` — would require destructuring at every match site and complicates serialization
- **Separate BrowserSession struct** — would duplicate most Session fields and complicate the session manager's `Vec<Session>`
**Consequences**:
- Pro: Simple serialization, easy backward compatibility with `#[serde(default)]`
- Pro: Minimal changes to existing Session consumers
- Con: Optional fields are technically possible on Shell sessions (data model doesn't enforce exclusivity — acceptable for two types; if more session types are added later, this should be revisited with an enum-variant approach or a trait-based design)

### Port Allocation: Counter-based from 19300

**Choice**: Atomic counter starting at port 19300, incrementing per browser session
**Why**: Each browser session needs a unique CDP port. A simple counter avoids port conflict detection complexity. 19300 is well above typical service ports and unlikely to collide with user services.
**Alternatives Considered**:
- **OS-assigned port (`--remote-debugging-port=0`)**: Would require parsing Chromium's stderr to discover the port, but VTE's PTY captures stderr into the terminal — we can't intercept it programmatically.
- **Port scanning**: Overly complex for this use case.
**Consequences**:
- Pro: Simple, deterministic
- Con: If 100+ browser sessions are created, ports may collide with other services (extremely unlikely in practice)

**Collision handling**: If Carbonyl fails to start (detected via immediate `child-exited` with non-zero status), log the error with the port number. The session is destroyed normally. The user sees the browser tab disappear — the same as if Carbonyl itself crashed. No special retry logic; port collisions at 19300+ are effectively impossible in normal use.

## System Behavior

### Scenario: Create browser session via keybinding

**Given**: User is in any tab
**When**: User presses `Ctrl+Shift+O`
**Then**: URL input modal appears centered in the overlay. User types URL and presses Enter. If URL lacks protocol, `https://` is prepended. Browser session is created with Carbonyl rendering the page. Sidebar shows globe icon + page title + URL.
**Rationale**: Overlay modal follows DES-007 pattern (works in both normal and dropdown mode without focus loss).

### Scenario: Create browser session via context menu

**Given**: User right-clicks on a detected URL (non-file) in any terminal
**When**: "Open in browser tab" is clicked
**Then**: Browser session is created immediately with that URL. No modal needed — the URL is already known.
**Rationale**: Reduces friction for the common case of following a URL from terminal output.

### Scenario: Browser process exits

**Given**: A browser session is active
**When**: Carbonyl process exits (user quit via `q`, crash, or kill)
**Then**: Session is destroyed immediately. Focus moves to the next appropriate session. No fallback to shell. URL poll timer is removed.
**Rationale**: Browser sessions are fundamentally different from shell sessions — exiting the browser means the user is done with that content.

### Scenario: Carbonyl not found on system

**Given**: User attempts to create a browser session
**When**: `which carbonyl` fails (binary not in PATH)
**Then**: Error overlay dialog appears: "Carbonyl is not installed. Install it with: npm install -g carbonyl". No session is created.
**Rationale**: Clear user feedback prevents confusion about why nothing happened.

### Scenario: Restore browser session after restart

**Given**: State file contains a browser session with URL and page title
**When**: seemux starts up and restores sessions
**Then**: If Carbonyl is available, browser session is restored with saved URL. If Carbonyl is no longer available, the session is skipped with a warning logged, and other sessions restore normally.
**Rationale**: Graceful degradation — missing browser binary shouldn't block other session restoration.

### Scenario: Multiple browser sessions

**Given**: User has two browser sessions open
**When**: Each navigates to different URLs
**Then**: Each session has its own CDP port and URL poll timer. Sidebar independently tracks URL and title for each. Closing one does not affect the other.
**Rationale**: Sessions are independent — each Carbonyl instance has its own Chromium process and debug port.

### Scenario: CDP poll failure

**Given**: A browser session is active with URL polling
**When**: HTTP GET to `/json/list` fails (Carbonyl crashed but VTE hasn't signaled child-exited yet)
**Then**: Poll silently fails. Sidebar retains last known URL and title. Next successful poll updates normally. When child-exited fires, session is destroyed and poll timer is removed.
**Rationale**: Transient failures shouldn't disrupt the user. The child-exited signal is the authoritative lifecycle event.

### Scenario: Split attempt on browser session

**Given**: A browser session is active (single Carbonyl pane)
**When**: User presses Ctrl+Shift+H or Ctrl+Shift+E (split horizontal/vertical)
**Then**: Split action is ignored for browser sessions. The session remains a single pane. The keyboard shortcut proceeds normally (doesn't consume the event for other sessions).
**Rationale**: Carbonyl renders to a single terminal widget — splitting would require a second browser process in a new pane, which doesn't map to the "one URL per session" model. Future layout support (DLT-002) will let users place separate sessions side-by-side instead.

## Notes

- Carbonyl emits OSC 2 (`\x1b]2;{title}\x07`) for page titles via its `set_title()` method in `src/output/renderer.rs`. VTE's `window_title_changed` signal will fire with page titles. This provides an additional (redundant) title tracking path alongside CDP polling.
- Carbonyl does NOT emit OSC 7 for URLs. The CDP HTTP polling approach is necessary.
- The `minreq` crate is synchronous and lightweight (~50KB), fitting the single-threaded GTK model without introducing an async runtime.
- Carbonyl's Chromium dependencies on Linux may be non-trivial. The error message should guide users to installation methods (npm, Docker, binary).

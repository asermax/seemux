# Design: DLT-004 - Open web pages in browser tabs

**Delta Spec**: [../delta-specs/DLT-004.md](../delta-specs/DLT-004.md)
**Status**: Draft

## Purpose

This document explains the design rationale for this delta: the modeling choices, data flow, system behavior, and architectural approach.

After implementation, the "Detected Impacts" section will guide reconciliation into feature design docs.

## Problem Context

Users working in seemux need to view web content (documentation, dashboards, search results) alongside terminal sessions without leaving the application. Currently, opening a URL means switching to an external browser, breaking the terminal-focused workflow.

The key constraints are:
- The browser must render inside a VTE terminal widget (the only embeddable terminal widget available in GTK4)
- seemux runs a single-threaded GTK event loop with `Rc<RefCell<T>>` state — no async runtimes
- Browser panes must participate in the existing split pane system, enabling shell + browser side-by-side within a session
- The browser binary is fixed (not user-configurable), so availability varies by system

## Design Overview

Add a new pane type — **Browser** — that spawns [Carbonyl](https://github.com/fathyb/carbonyl) (a Chromium-based terminal browser) inside a VTE terminal widget. Browser panes can exist as standalone sessions (new tab) or as split panes within an existing session, tracked per-pane alongside the existing per-pane CWD tracking.

The design introduces:
1. **SessionType enum** on Session and per-pane browser state (URL, page title, debug port) tracked in SessionManager alongside existing per-pane CWD
2. **Browser session factory** (`create_browser_session`) and **browser split method** (`split_with_browser`) in SessionManager
3. **URL polling** via HTTP GET to Chromium's `/json/list` endpoint per browser pane, updating sidebar and persistence
4. **Adapted TabRow** display that switches icon, title, and subtitle based on the focused pane's type
5. **Two context menu entries**: "Open in new tab" (new session) and "Open in split" (new browser pane in current session)
6. **URL input modal** (overlay dialog) for the keybinding path

## Components

### Implementation Structure

| Layer/Component | Responsibility | Key Decisions |
|-----------------|----------------|---------------|
| **Session model** (`session/mod.rs`) | `SessionType` enum on Session; browser state tracked per-pane in SessionManager | SessionType reflects session's original type; browser state (url/page_title/debug_port/poll_timer) in `HashMap<PaneId, BrowserPaneState>` |
| **Session manager** (`session/manager.rs`) | `create_browser_session(url)`, `split_with_browser(url)` factories; per-pane port allocation; per-pane URL poll timers | Follows existing `session_cwds` HashMap pattern for per-pane state |
| **VTE terminal** (`terminal/vte_terminal.rs`) | No changes — Carbonyl runs inside it like any command | Reuses existing `spawn_command` and signal infrastructure |
| **Sidebar TabRow** (`sidebar/tab_row.rs`) | Conditional display by focused pane type | `set_session_type(SessionType)` switches icon/metadata; sidebar updates on pane focus change |
| **Actions** (`app/actions.rs`) | `open-in-browser` and `open-in-browser-split` GIO actions; context menu additions | Follows DES-004; both actions shown only for non-file URLs |
| **Dialogs** (`app/dialogs.rs`) | `show_url_input_overlay` for browser tab creation | Follows DES-007 (Overlay Dialog Pattern); reuses `show_entry_overlay` pattern |
| **Keyboard** (`app/keyboard.rs`) | `Ctrl+Shift+O` keybinding | Added to `is_our_shortcut` match and handler chain |
| **Persistence** (`config.rs`) | `SavedSplitNode::Leaf` extended with browser fields; `SavedSession` gets `session_type` | `session_type` defaults to Shell for backward compat (serde default) |
| **URL Polling** (in `session/manager.rs`) | HTTP GET to Chromium's `/json/list` per browser pane every 500ms | Uses `minreq` (synchronous, no async runtime); per-pane GLib timeout |

### Cross-Layer Contracts

**Integration Points**:
- **SessionManager ↔ Sidebar**: When focused pane changes (via `wire_pane_focus`), update sidebar to reflect focused pane's type (globe vs folder icon, URL vs CWD, page title vs folder name)
- **SessionManager ↔ URL Poll**: Per-pane poll timer closure captures pane ID and sidebar reference; on URL/title change, updates `BrowserPaneState` and sidebar, marks persistence dirty
- **Actions ↔ SessionManager**: `open-in-browser` calls `create_browser_session(url)`; `open-in-browser-split` calls `split_with_browser(url)`
- **Keyboard ↔ Dialogs**: `Ctrl+Shift+O` calls `show_url_input_overlay()` which on submit calls `create_browser_session(url)`
- **Context Menu ↔ Actions**: Menu items activate `win.open-in-browser` or `win.open-in-browser-split` with URL parameter

**Error handling**:
- Carbonyl not found: show error overlay dialog with installation instructions, no session/pane created
- Carbonyl fails to start: VTE `child-exited` fires immediately → pane closes → session continues or destroys if last pane
- CDP port unreachable: URL polling silently fails (up to 10 consecutive failures, then stops); sidebar shows initial URL only; title may still update via VTE's `window_title_changed` signal (OSC 2)
- Port collision: Carbonyl fails to bind port → child-exited with error → pane closes, error logged with port number

### Shared Logic

- **URL normalization**: Auto-prepend `https://` if input lacks a protocol — shared between modal submit and context menu actions
- **Port allocation**: Counter-based port assignment starting at 19300, stored in SessionManager — one port per browser pane
- **BrowserPaneState**: Shared struct holding `url`, `page_title`, `debug_port`, `poll_timer: Option<SourceId>` — stored per pane ID in SessionManager

### Layout Explanation (Browser Tab Row)

**Purpose**: Shows browser pane metadata in the sidebar, distinct from shell panes at a glance.

**Key elements**: Globe icon replaces folder icon. Page title replaces folder name as the primary title. URL replaces display path as the subtitle. No git branch or PR badge (skipped for browser panes). Status pill and close button unchanged.

**Layout rationale**: Visual distinction (icon + metadata swap) makes browser panes immediately identifiable without breaking the tab row layout. Adapting per focused pane (rather than per session) naturally handles mixed sessions.

**Interactions**: Same as shell tab rows — click to activate, drag to reorder, close button to destroy. Middle-click/peek behavior unchanged.

## Modeling

### Per-Pane Browser State

Browser state is tracked per-pane in SessionManager, mirroring the existing `session_cwds` pattern:

```
SessionManager
├── session_cwds: RefCell<HashMap<PaneId, String>>          (existing — per-pane CWD)
├── browser_panes: RefCell<HashMap<PaneId, BrowserPaneState>> (NEW — per-pane browser state)
└── ...

BrowserPaneState
├── url: String
├── page_title: Option<String>
├── debug_port: u16
├── poll_timer: Option<glib::SourceId>
├── consecutive_failures: u32
```

When a pane's child process exits, its `BrowserPaneState` entry (if any) is removed and its poll timer is cancelled — matching how `session_cwds` entries are cleaned up in `close_pane`.

### Session Type

```
Session
├── id: String (existing)
├── title: String (existing)
├── status: SessionStatus (existing)
├── session_type: SessionType (NEW)
│   ├── Shell (default)
│   └── Browser
├── cwd: Option<String> (existing)
├── ... (remaining existing fields — no browser fields on Session)
```

`SessionType` on Session indicates the session's original type. A session created via `create_browser_session` has type `Browser`. A shell session with a browser pane added via split still has type `Shell`. The sidebar tab row displays metadata from the **focused pane** regardless of session type.

### SavedSession Extension

```
SavedSession (JSON)
├── title: String (existing)
├── split_tree: SavedSplitNode (existing — Leaf nodes gain optional browser fields)
├── group_id: String (existing)
├── session_type: Option<SessionType> (NEW — defaults to Shell)
```

```
SavedSplitNode::Leaf (extended)
├── cwd: Option<String> (existing)
├── url: Option<String> (NEW — for browser pane restoration)
├── page_title: Option<String> (NEW — for sidebar display on restore)
```

Backward compatibility: `session_type` and leaf-level browser fields use `#[serde(default)]`, so old state files deserialize correctly.

## Data Flow

### Browser Session Creation (via modal)

```
User presses Ctrl+Shift+O
    → keyboard handler calls show_url_input_overlay()
    → User types URL, presses Enter
    → normalize_url() prepends https:// if needed
    → manager.create_browser_session(url)
        → Session::new() with SessionType::Browser
        → create SplitView with single Leaf
        → allocate debug port (19300 + counter)
        → VTE spawn_command(["carbonyl", "--remote-debugging-port=PORT", url])
        → wire child-exited → close_pane (existing pattern)
        → wire title_changed → update page title via browser_panes
        → start per-pane URL poll timer (500ms GLib timeout)
        → register BrowserPaneState in browser_panes HashMap
        → register session in sidebar with browser icon
```

### Browser Pane Creation (via split)

```
User right-clicks on URL → "Open in browser split"
    → activates "win.open-in-browser-split" action with URL
    → manager.split_with_browser(url)
        → call existing split logic (SplitView.split)
        → for the NEW pane:
            → allocate debug port
            → VTE spawn_command(["carbonyl", "--remote-debugging-port=PORT", url])
            → wire signals (same as create_browser_session)
            → register BrowserPaneState
        → session continues with both shell and browser panes
        → sidebar shows focused pane's metadata
```

### URL + Title Tracking (per pane)

```
Every 500ms (per-pane GLib timeout):
    → GET http://127.0.0.1:{debug_port}/json/list
    → Parse JSON array, find target where type == "page"
    → Extract url and title fields
    → If URL changed from last poll:
        → Update BrowserPaneState.url
        → If this pane is focused in its session:
            → Update sidebar subtitle (URL display)
        → Mark persistence dirty (DES-003)
    → If title changed from last poll:
        → Update BrowserPaneState.page_title
        → If this pane is focused in its session:
            → Update sidebar title
```

**CDP `/json/list` response format** (single page target):
```json
[
  {
    "id": "ABCDEF123",
    "type": "page",
    "title": "Example Page Title",
    "url": "https://example.com/page",
    "webSocketDebuggerUrl": "ws://127.0.0.1:19300/devtools/page/ABCDEF123"
  }
]
```

Target selection: find first entry where `"type" == "page"`. Ignore `browser` and `service_worker` entries.

**Error handling**:
- HTTP connection refused / timeout: silent failure, retain last known values. The poll runs on the next 500ms tick.
- JSON parse error: silent failure. Malformed response shouldn't crash the poll loop.
- Empty target array: treat as "no page loaded yet" — retain initial URL.
- Consecutive failures (10+): stop polling (Carbonyl likely dead). The `child-exited` signal handles cleanup.

### Pane Focus Change

```
User clicks or navigates to a different pane within a session
    → existing wire_pane_focus callback fires
    → check if focused pane has BrowserPaneState:
        → Yes: sidebar shows globe icon + page_title + URL
        → No: sidebar shows folder icon + CWD + git branch (existing behavior)
```

### Session Persistence

```
On save (debounced):
    → For each session, map to SavedSession
    → For each Leaf in split_tree:
        → If pane has BrowserPaneState: serialize url and page_title
        → Shell panes: url/page_title are None (backward compat)

On restore:
    → Load SavedSession array from JSON
    → For each Leaf with url field:
        → If Carbonyl available: spawn Carbonyl with saved URL, start poll timer
        → If Carbonyl not found: skip that pane (log warning), continue with shell panes
    → Shell panes: normal restore flow
```

### Pane Destruction (browser pane)

```
Carbonyl process exits (user quit, crash, kill)
    → VTE child-exited signal fires
    → close_pane(session_id, pane_id)
        → Cancel and remove poll timer from BrowserPaneState
        → Remove BrowserPaneState from browser_panes HashMap
        → Close pane in SplitView
        → If last pane in session → destroy_session (existing behavior)
        → If other panes remain → rebuild widget tree, focus surviving pane
```

## Key Decisions

### Browser Binary: Carbonyl

**Choice**: Carbonyl (Chromium-based terminal browser)
**Why**: Only terminal browser that renders full modern web pages inside a VTE widget. Starts in <1s, runs at 60 FPS, idles at 0% CPU. Actively maintained (19k GitHub stars). Accepts URLs as CLI arguments.
**Sources**: [Carbonyl GitHub](https://github.com/fathyb/carbonyl), researched May 2026
**Options Researched**:
- **Lynx**: Text-only, no JavaScript/CSS, oldest terminal browser. `UPDATE_TERM_TITLE` option for title tracking but no modern web rendering.
- **w3m**: Lightweight, some table/frame support, no JavaScript. No documented OSC sequence emission.
- **Browsh**: Firefox headless + automation protocol. 50x more CPU than Carbonyl for same content. More complex dependencies (requires Firefox).
**Why This Over Alternatives**: Carbonyl is the only option that renders modern web pages (CSS, JavaScript, WebGL, video) inside a terminal at native performance. The alternatives either lack modern web support (Lynx, w3m) or have prohibitive resource costs (Browsh).
**Consequences**:
- Pro: Full web rendering in terminal, excellent performance, active development
- Con: Requires Chromium dependencies on Linux; npm or binary installation; no fullscreen mode yet

### URL Tracking: CDP HTTP Polling

**Choice**: HTTP polling of Chromium DevTools `/json/list` endpoint every 500ms per browser pane
**Why**: Carbonyl passes unknown CLI args through to Chromium, so `--remote-debugging-port` works out of the box. The `/json/list` endpoint returns both `url` and `title` fields in a simple JSON array. No WebSocket, no async runtime, no Carbonyl modification needed.
**Sources**: Chromium DevTools Protocol documentation, Carbonyl source code analysis (`bridge.rs` line 126: `.args(cmd.args)`)
**Options Researched**:
- **Fork Carbonyl + add OSC 7 emission**: Clean but requires maintaining a fork. The `push_nav()` method in Carbonyl's `Navigation` struct already has the URL — adding `\x1b]7;{url}\x07` would be ~3 lines. VTE handles OSC 7 via `current_directory_uri_changed`. Rejected because it adds a fork maintenance burden.
- **WebSocket CDP events (Page.frameNavigated)**: Near-instant updates, well-documented. Rejected because it requires a WebSocket client library, async handling, and more complex message parsing — overkill for sidebar URL display.
- **Terminal output parsing**: Fragile, depends on Carbonyl's internal UI layout. Rejected.
- **Initial URL only (no navigation tracking)**: Violates R9 (must-have requirement). Rejected.
**Why This Over Alternatives**: Simplest approach that works without modifying Carbonyl. Uses Chromium's built-in CDP endpoint. `minreq` (synchronous HTTP client) fits GTK's single-threaded model perfectly — no tokio needed.
**Consequences**:
- Pro: Zero modification to Carbonyl, simple implementation, synchronous fits GTK model
- Pro: Gets both URL and title from single endpoint
- Con: 500ms latency on URL updates (acceptable for sidebar display)
- Con: No same-document navigation tracking (hash changes, pushState) — `/json/list` may not reflect these
- Con: Requires `minreq` dependency (~50KB)
- Con: Debug port open on localhost while browser pane is active (127.0.0.1 only, acceptable risk)

**HTTP client choice**: `minreq` chosen over `ureq` (larger, more features than needed), `reqwest` (requires tokio runtime), and `attohttpc` (similar scope but less widely adopted). `minreq` provides exactly what's needed — synchronous GET with JSON response body — in ~50KB, with no dependency on an async runtime.

### Per-Pane State (not per-session)

**Choice**: Browser state (URL, page title, debug port, poll timer) tracked per-pane in SessionManager via `HashMap<PaneId, BrowserPaneState>`, mirroring the existing `session_cwds` HashMap
**Why**: A session can have mixed pane types (shell + browser). The existing architecture already tracks per-pane state (CWD via `session_cwds`, signal handlers via `wire_vte_signals`). Adding browser state to the same per-pane pattern is the natural extension — no new architectural concepts needed.
**Alternatives Considered**:
- **Per-session state with single-pane restriction**: Simpler but prevents the split use case (shell + browser side-by-side). Rejected because split support is a natural workflow.
- **Browser state on the SplitTree Leaf node**: Would require modifying the lightweight `SplitTree` enum to carry heavy state. The HashMap approach keeps the tree structure simple (just IDs).
**Consequences**:
- Pro: Natural fit with existing architecture, enables mixed sessions
- Pro: Browser pane cleanup is trivial — remove HashMap entry in `close_pane`
- Con: Slightly more indirection than per-session state

### Keybinding: Ctrl+Shift+O

**Choice**: `Ctrl+Shift+O` (O for "Open in browser")
**Why**: `Ctrl+Shift+B` was the original candidate but is already used for sidebar collapse toggle. `O` is a natural mnemonic ("Open browser") and fits the existing `Ctrl+Shift+` modifier pattern.
**Alternatives Considered**:
- `Ctrl+Shift+B`: Already used for sidebar collapse (line 89 of `keyboard.rs`)
- `Ctrl+Shift+N`: Claimed in `is_our_shortcut` list but not explicitly handled — confusing
- `Ctrl+Shift+G`: Same situation as N
**Consequences**:
- Pro: Memorable mnemonic, consistent with existing shortcuts
- Con: None significant

### Port Allocation: Counter-based from 19300

**Choice**: Atomic counter starting at port 19300, incrementing per browser pane
**Why**: Each browser pane needs a unique CDP port. A simple counter avoids port conflict detection complexity. 19300 is well above typical service ports and unlikely to collide with user services.
**Alternatives Considered**:
- **OS-assigned port (`--remote-debugging-port=0`)**: Would require parsing Chromium's stderr to discover the port, but VTE's PTY captures stderr into the terminal — we can't intercept it programmatically.
- **Port scanning**: Overly complex for this use case.
**Consequences**:
- Pro: Simple, deterministic
- Con: If 100+ browser panes are created, ports may collide with other services (extremely unlikely in practice)

**Collision handling**: If Carbonyl fails to start (detected via immediate `child-exited` with non-zero status), log the error with the port number. The pane closes normally. The user sees the browser pane disappear — the same as if Carbonyl itself crashed. No special retry logic; port collisions at 19300+ are effectively impossible in normal use.

### Context Menu: Two Options

**Choice**: "Open in browser tab" (new session) and "Open in browser split" (new pane in current session)
**Why**: The two options map to the two ways users want to view web content alongside their work. "New tab" for dedicated browsing; "split" for quick reference alongside the current terminal. Both are common workflows (e.g., reading docs next to code).
**Consequences**:
- Pro: Flexible — user chooses the layout that fits their workflow
- Con: Two more menu items in an already populated context menu (acceptable — they only appear when a URL is detected)

## System Behavior

### Scenario: Create browser session via keybinding

**Given**: User is in any tab
**When**: User presses `Ctrl+Shift+O`
**Then**: URL input modal appears centered in the overlay. User types URL and presses Enter. If URL lacks protocol, `https://` is prepended. New browser session created with Carbonyl rendering the page. Sidebar shows globe icon + page title + URL.
**Rationale**: Overlay modal follows DES-007 pattern (works in both normal and dropdown mode without focus loss).

### Scenario: Create browser session via context menu (new tab)

**Given**: User right-clicks on a detected URL (non-file) in any terminal
**When**: "Open in browser tab" is clicked
**Then**: New browser session is created immediately with that URL. No modal needed — the URL is already known.
**Rationale**: Fastest path for "I want to view this in a separate tab."

### Scenario: Create browser pane via context menu (split)

**Given**: User right-clicks on a detected URL (non-file) in a terminal
**When**: "Open in browser split" is clicked
**Then**: Current session's active pane is split. New pane spawns Carbonyl with the URL. Original shell pane remains. Sidebar tab row shows browser metadata (globe icon + URL) since the new browser pane is focused.
**Rationale**: Enables viewing documentation alongside terminal output in the same session — the most common browser use case.

### Scenario: Browser pane exits in a split session

**Given**: A session has both a shell pane and a browser pane (created via split)
**When**: Carbonyl process exits (user quit via `q`, crash, or kill)
**Then**: Browser pane closes. Shell pane continues. Session remains alive. Sidebar updates to show shell metadata (folder icon + CWD). Poll timer is removed.
**Rationale**: Same behavior as shell pane exit — pane closes, session survives if other panes exist. Consistent with the existing split pane lifecycle.

### Scenario: Browser pane exits in a browser-only session

**Given**: A browser-only session (single Carbonyl pane, created via keybinding or "new tab")
**When**: Carbonyl process exits
**Then**: Last pane closes → session is destroyed. Focus moves to the next appropriate session.
**Rationale**: Natural consequence of the existing "last pane closes → session destroyed" rule. No special handling needed.

### Scenario: Carbonyl not found on system

**Given**: User attempts to create a browser session or split
**When**: `which carbonyl` fails (binary not in PATH)
**Then**: Error overlay dialog appears: "Carbonyl is not installed. Install it with: npm install -g carbonyl". No session or pane is created.
**Rationale**: Clear user feedback prevents confusion about why nothing happened.

### Scenario: Restore browser pane after restart

**Given**: State file contains a Leaf node with url field
**When**: seemux starts up and restores sessions
**Then**: If Carbonyl is available, browser pane is restored with saved URL in the appropriate split position. If Carbonyl is no longer available, that pane is skipped with a warning logged, and other panes in the session restore normally.
**Rationale**: Graceful degradation — missing browser binary shouldn't block other session/pane restoration.

### Scenario: Multiple browser panes across sessions

**Given**: User has a browser-only session and a shell session with a browser split
**When**: Each browser pane navigates to different URLs
**Then**: Each browser pane has its own CDP port, poll timer, and `BrowserPaneState`. Sidebar independently tracks URL and title for the focused pane in each session. Closing one browser pane does not affect others.
**Rationale**: Panes are independent — each Carbonyl instance has its own Chromium process and debug port.

### Scenario: CDP poll failure

**Given**: A browser pane is active with URL polling
**When**: HTTP GET to `/json/list` fails (Carbonyl crashed but VTE hasn't signaled child-exited yet)
**Then**: Poll silently fails. Sidebar retains last known URL and title. Next successful poll updates normally. When child-exited fires, pane closes and poll timer is removed.
**Rationale**: Transient failures shouldn't disrupt the user. The child-exited signal is the authoritative lifecycle event.

### Scenario: Pane focus change in mixed session

**Given**: A session has both shell and browser panes
**When**: User navigates between panes (Alt+HJKL or click)
**Then**: Sidebar tab row updates to reflect the newly focused pane's metadata. Browser pane shows globe icon + URL + page title. Shell pane shows folder icon + CWD + git branch.
**Rationale**: Consistent with how CWD already updates per focused pane. No new concept introduced.

## Notes

- Carbonyl emits OSC 2 (`\x1b]2;{title}\x07`) for page titles via its `set_title()` method in `src/output/renderer.rs`. VTE's `window_title_changed` signal will fire with page titles. This provides an additional (redundant) title tracking path alongside CDP polling.
- Carbonyl does NOT emit OSC 7 for URLs. The CDP HTTP polling approach is necessary.
- The `minreq` crate is synchronous and lightweight (~50KB), fitting the single-threaded GTK model without introducing an async runtime.
- Carbonyl's Chromium dependencies on Linux may be non-trivial. The error message should guide users to installation methods (npm, Docker, binary).
- The per-pane browser state design aligns with the existing `session_cwds` HashMap pattern and `close_pane` cleanup logic, minimizing new architectural concepts.
